# 角色素材库规格

角色是「一个人能反复出镜」这件事的最小单位：一个名字 + 一张脸 + 一套可复现的样貌标记。
这份文档定义**一个角色什么时候算创建完成**，以及完成度怎么判。

角色资产存在 **museav 中台**（`museav subjects`），reel-kit 负责 **0→1 的交互引导** 与
**本地镜像**（读得回来、看得见缺件），不另造一套角色数据库。

## 分工边界

| 职责 | 归属 | 说明 |
| --- | --- | --- |
| 角色资产存储（主体 + 视图 + 体貌 traits） | **museav 中台** | 唯一真源（SSOT） |
| 0→1 创建交互（一张脸 → 完整角色） | reel-kit | 只做交互与编排，生成动作都调中台 |
| AI 视频生成（仿真人出镜画面） | museav 中台 | 图生视频，reel-kit 不造视频引擎 |
| 视频脚本（逐句文案） | reel-kit | 现有逐句驱动 |
| 本地流水线（TTS + 字幕 + BGM + ffmpeg） | reel-kit | 现有 compose 核心 |

**reel-kit 不生成视频画面。** 角色相关的出图、出视频一律走中台；本地只做配音与合成。

## 完成判定

> **完成 = 字段齐 + 五视图齐。缺任一件 = 未完成（draft），不放行进仿真人视频流水线。**
>
> 另有**同源**一项：能证明五视图不是同一批定妆的，同样拦住（会漂）；
> 无法确认的，**只提示风险、不硬拦** —— 判定要诚实，不把「不知道」当「达标」。

判定分三类结果，界面分开显示：

| 结果 | 含义 | 界面 |
| --- | --- | --- |
| `missing` | 缺名称 / 缺视图 / 缺体貌等，补上就好 | 点名缺哪一项 |
| 硬拦：同源不一致 | 能证明五视图来自不同批次，会漂 | 点名并阻止出片 |
| `warnings` | 无法确认同源等风险 | 提示但不拦 |

### 1. 必填字段

| 字段 | 中台来源 | 要求 |
| --- | --- | --- |
| 名称 `name` | `subjects create --name` | 1–60 字；同项目下同类不可重名 |
| 人物来源 `persona` | `subjects create --persona` | `real` 真人 / `virtual` 虚拟人 |
| 体貌 `traits` | `subjects create --traits` | 至少 **发型 / 脸型 / 肤色 / 体型** 四项，JSON 对象 |
| 基准人脸 | `subjects add-asset --role raw` | 一张能看清五官的正面照 |

服装、配饰、鞋靴可选，但**强烈建议填写**：它们是出图时锁定造型的主要依据，
缺了会导致同一角色在不同镜头里穿着不一致。

### 2. 五视图（全身正交转面组，缺一不可）

| 视图 | 中台 role | 镜像里的本地 role |
| --- | --- | --- |
| 正面 | `view_front` | `front` |
| 左 45° | `raw`（靠 `--name` 归位） | `left45` |
| 正侧面 | `view_side` | `side` |
| 右 45° | `raw`（靠 `--name` 归位） | `right45` |
| 背面 | `view_back` | `back` |

**中台的 role 词表只有三视图**（`view_front` / `view_side` / `view_back`），两个 45° 视角
没有专属 role。处理办法：45° 落在 `raw`，用 `--name "<角色名>-左45°"` / `"<角色名>-右45°"`
命名归位。**门禁以本地五视图为准，不因为中台只认三视图就把标准降到三视图。**

### 3. 视觉标记（一致性能不能锁住）

五张图必须来自**同一次角色定妆**，而不是五次各自独立的生成 —— 每次独立生成都会漂。

**但「同源」不能假装能自动验。** 中台的 `gen_job_id` 是逐图的（批量出图每行一个 job），
拿它判同源会把同批的 5 张误判成漂移。真正知道「这五张是不是照着同一张基准脸、
同一轮生成的」只有发起 0→1 创建的那一方。所以：

- 0→1 流程给这一轮产出的五视图打一个**同源批次标记**，存进本地镜像；
- 判定时按这个标记：**能证明不是同一批 → 硬拦**（会漂，不该进流水线）；
- **无法确认（没记录）→ 只提示风险、不硬拦** —— 可能是在别处建的合法角色；
- 不把「没记录」当达标，也不猜一个批次号糊弄。

同源只靠标记还不够，出图时就要锁死一致性：以**基准人脸**为唯一参考图（`--ref`），
提示词里写明「五官、发型、肤色、身材、服装完全一致，不得漂移」。

## 状态机

```
draft ──(字段齐 + 五视图齐 + 标记达标)──> complete
```

- `draft`：可以随时保存、可以改、补图；但**不能**作为仿真人视频的取角来源。
- `complete`：五视图齐备，可用于图生视频与出镜流水线。

界面上的完成度是**可解释的**：显示缺了哪一项（缺哪个视图 / 缺哪个字段），
而不是只给一个「未完成」。

## 0→1 创建流程

用户只需要上传**一张人脸**。

1. 填名称、选 `real` / `virtual`、填体貌 traits → `subjects create` 建主体。
2. 上传的人脸 → `subjects add-asset --role raw`，作为基准图。
3. 以基准人脸为参考，用**多视角角色卡模板**补齐五视图（每视图一次生成）。
4. 五张图逐个 `subjects add-asset` 登记到主体。
5. 重新拉取主体 → 按上面的判定算出 `complete` / `draft` + 缺件清单。

第 3 步的关键：**五视图要一次定妆**。做法是先用一次生成产出角色卡大图
（16:9 多模块设定集），再从大图切出五张独立视图分别登记 —— 这样五张图天然同源，
不会各生成各的漂。
