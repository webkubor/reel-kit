# Reel Studio 2.0 产品与实施规划

> 状态：讨论草案 · 2026-11-11。本文提出优先级和可验证的交付顺序，不代表功能已完成、排期已承诺或范围已获得最终确认。
>
> 基线：已公开发布的 `app-v1.6.0`（Wails 桌面版）；历史目标、既有验收和事故记录见 [1.0 计划](studio-plan.md)。历史 Node 工作台中的能力是可研究的既有资产，不代表已接入当前桌面版。

## 1. 目标与边界

**目标：让创作者能持续制作、找回并改进短视频，而不是每次从零填写。** 2.0 应同时解决可靠保存、逐镜修改、跨平台交付和过程可追溯，再逐步接回已有项目推荐与制作方法能力。

1. **本地桌面优先**：Wails + Go 直接绑定；不携带 Node 运行时，不启动本地 HTTP 业务服务，不依赖常驻中间件。本机语音、画面渲染和编码复用已有能力。
2. **AI 是可配置的辅助能力**：明确哪些内容会发送到外部、何时可能收费；本地制作流程不依赖外部 AI。模型归属只用上游回执，没有回执就记 `unknown`。
3. **先把真实交付做稳**：项目、输入、素材和运行记录退出后可找回；失败可定位、可恢复；公开平台的安装包必须经过对应平台实测。
4. **延续当前工作台方向**：浅色、薄荷绿与淡粉、轻玻璃按钮；左侧内容、右侧画面。新增交互围绕创作流程，不为堆功能重做整个界面。
5. **成果先过文件检查与人工审片**：自动检测只判断能证实的事实；可发布不等于文件生成成功，人工内容和视听审查不能被自动绿灯替代。

**范围冲突待厘清**：历史 [1.0 计划](studio-plan.md)提出 GitHub 项目推荐、商品介绍，以及发布回填和制作方法复盘；仓库 [AGENTS.md](../AGENTS.md) 对引擎定位写有「不生成视频、不剪辑已有视频、不是端到端生产线」。2.0 提案保留项目推荐和逐镜素材编排的候选，但不把通用时间线、视频剪辑、平台自动发布或自研生成模型列为既定范围；桌面产品与独立 CLI 的职责边界需要在实现相关功能前明确。外部视频生成若被纳入，也应是可选的上游服务适配，而非承诺自研模型。

## 2. 1.6.0 事实基线

| 已有 | 缺口与限制 |
|---|---|
| macOS Apple Silicon 安装包；Wails + Go，本地配音和短片合成 | Windows 版尚无本版安装包及真实 Windows 运行验收；macOS 包未公证 |
| 人物/商品介绍短片、横竖画幅、图片导入、播放和导出 | 编辑画面是示意；尚无逐镜素材编排与精确预览 |
| 项目、素材、成片及任务记录落盘 | 正在编辑的标题、文案、参数和分镜代码只保存在进程内，退出丢失 |
| OpenAI 兼容服务配置、钥匙串密钥、只读连接检查、AI JSON 分镜 | 已用模拟服务验收；各真实模型及图片/视频生成供应商尚未在新版桌面逐一联调 |
| 生成历史、提示词、请求/实际模型、步骤时间、错误 | 尚无统一每次制作快照、逐镜产物复用、质量检查和发布复盘闭环 |

证据来源：[当前 README](../README.md)、[桌面发版说明](desktop-release.md)、`apps/reel-studio-wails/` 实现；具体发布与测试结果以 GitHub Release 和对应运行记录为准。

## 3. 优先级与版本切分

| 顺序 | 交付 | 用户能获得什么 | 与 2.0 的关系 |
|---|---|---|---|
| **P0** | Windows 发布补齐 | Windows x64 用户能够安装、离线配音、制作并导出视频 | 1.x 交付欠项，优先单独发布，不等 2.0；具体版本号以实际发布时为准 |
| **P0** | 草稿和项目可靠性 | 退出、崩溃或升级后回到刚才的编辑内容，不覆盖已有成片和任务 | 2.0 基础 |
| **P1** | 分镜工作流 | 每镜独立编辑文案与素材，顺序可调整，预览与状态明确 | 2.0 核心 |
| **P1** | AI 和素材接入 | 选择受支持的服务和模型，查看请求内容、费用提示、结果与失败原因 | 2.0 可选增强；先做一个有真实回执的端到端适配 |
| **P1** | 项目推荐与内容来源 | 输入 GitHub 仓库生成可审阅的推荐分镜，说明信息来自哪里 | 继承旧计划目标，先验证当前产品范围 |
| **P1** | 作品检查与可复用制作方法 | 对成片做客观检测，记录人工审片和制作配置；复制方法再做一条 | 2.0 内容质量闭环 |
| **P2** | 发布记录、表现回填和复盘 | 手动记录平台、链接及观察窗口，比较内容版本 | 在核心制作稳定后逐步交付，不阻塞第一条视频 |
| **P2** | 声音库、更多模板和供应商 | 复用授权素材及音色，扩展创作选择 | 按授权、资源和真实设备验收决定具体范围 |

这些是工作顺序，不是日期承诺。单个平台发布、功能合入、应用发布及用户验收分别记录，不能互相替代。

## 4. 主要用户流程

1. **选择入口**：人物/商品介绍；项目推荐作为候选入口，只有内容来源链路可用并通过验收才开放。
2. **准备分镜**：手动输入或让 AI 起草；每镜可修改文字、替换图片、调整顺序，明确显示未保存、已保存与错误状态。JSON 代码与可视化编辑使用同一份数据，错误不覆盖最后有效草稿。
3. **确认制作**：展示画幅、语音、镜数、素材来源和将要调用的外部服务。付费调用前显示可能收费；无法可靠估价就明确写未知。
4. **执行与恢复**：逐步显示排队、执行、完成、失败、取消和中断；呈现素材/模型来源、回执、耗时与产物。网络断开或重启后不重复提交付费任务；可恢复时按上游任务 ID 查询。
5. **检查与导出**：应用内播放真实成片；显示尺寸、时长、音视频流等客观结果，以及需要用户确认的内容、字幕和声音检查项。导出前后均保留原项目。
6. **再制作**：可以复制既有项目的设置创建新项目，或调整当前项目；原有成片、生成记录和配置快照保持不变。可复用哪些结果以明确的依赖关系和实际验证为准。

## 5. 分阶段实施和验收

### 阶段 A：补齐 Windows 与项目保存

- Windows x64：在 Windows runner 构建 Wails 应用，收集并验证 Windows 版 sherpa、模型、渲染器、ffmpeg 与 ffprobe；明确资源许可、下载来源、校验和、包体积、签名状态。不能把 Go 交叉编译通过或旧版安装包当作新版发布证据。
- 对对应平台的真实安装包做启动、新建项目、导入图片、离线中文配音、单镜及多镜成片、播放和导出；记录实际系统版本、包版本、结果、限制和测试设备。Windows 真机不可用时标记阻塞，不宣布 Windows 已验收。
- 草稿：保存标题、副标题、画幅、分镜及其编辑模式、素材选择和制作设置；项目切换、退出重启、异常中断后恢复。使用版本化数据结构与原子写入；升级前备份、失败可回退、旧数据保留，不自动删除或推测历史信息。
- 验收：隔离数据根下测试新建、修改、切项目、重启、损坏文件、磁盘写入失败；旧 1.6 项目和历史视频可打开；人工或合成测试数据不得触及用户真实项目。

### 阶段 B：逐镜编辑与过程可见

- 镜头作为明确的数据对象，拥有稳定 ID、文字、关联素材、顺序及可验证的制作状态。逐镜新增、删除和排序须保留未修改镜头；危险操作有撤销或可恢复路径。
- 使用已有渲染与合成机制扩展逐镜输入；先测两镜不同图片和文案、重排、缺失素材与横竖画幅。不把示意画面描述为最终帧级预览。
- 制作记录冻结本次输入与配置，展示每步起止时间、结果和错误；历史成片与本次配置对应。提供可复制的脱敏诊断信息，不能暴露密钥或私有素材。
- 缓存复用先限定可验证场景：改某镜文案时，仅在依赖、资源和引擎版本匹配的条件下复用不受影响产物；缺少证据时重做并说明，不能错误复用旧画面或声音。

### 阶段 C：模型适配与项目推荐

- 保留当前 OpenAI 兼容分镜能力；按能力类型区分文字、图片、视频和语音服务。先审查 `src/studio/providers.mjs`、`src/studio/channels.mjs`、`src/studio/recommendation.mjs` 的现有协议与场景，在 Go 侧复用契约和验证过的算法，不把 Node 服务器带入桌面包。
- 每个适配器声明可用能力、输入、结果、取消/查询行为；实际模型、上游任务 ID、计费信息以真实回执为准。提交可能计费的请求不做盲目自动重试，网络失败与任务状态未知要区分。
- 先以模拟服务覆盖成功、错误、超时、取消和重启查询，再选择一条真实供应商路径完成端到端验收，记录实际模型回执、耗时、费用和授权范围。未完成真实联调的入口应标记未验证。
- 项目推荐先核对 URL 与可访问内容、保留来源和引用，AI 输出需人工审阅；无法读取时告知原因，不编造仓库事实。具体远程读取与隐私策略在实现前明确。

### 阶段 D：质量检查与可复用方法

- 自动检查使用现有 ffprobe/ffmpeg：实际画幅、视频/音频流、时长、可解码性及用户选择的目标；外部平台限制的来源和有效期可追踪，未知不填默认通过。
- 审片记录按内容、字幕、画面、声音列待确认项，检查结果绑定具体成片及其配置。重做后旧审片结论不自动套到新成片。
- 将制作方法作为不可变版本：记录来源、设置、修改说明和关联成片；复制方法与修改当前项目是两个操作。历史 Node 工作台已有的 `src/studio/workflow.mjs` 和测试用作行为依据，迁移前先核验契约和数据差异。
- 发布记录、表现回填、观察窗口及复盘先按手动输入设计；未知值留空。小样本比较注明局限，不自动将表现归因于某项设置。

## 6. 架构与数据草案

- **桌面界面**：Wails WebView 只通过 Go 绑定调用业务，图片与视频通过应用内资源机制展示；不新增本地 HTTP 业务服务。
- **Go 核心**：项目/草稿、分镜、素材、配置与任务统一版本化；沿用现有 `StudioStore`、任务队列、取消上下文、sherpa、渲染器与 ffmpeg，先补已有能力再引入新依赖。
- **对象关系**：项目包含可编辑草稿与素材引用；一次制作保存不可变输入/设置快照、步骤、产物和模型回执；检查结果绑定产物；制作方法有独立版本。外部密钥只留系统钥匙串，不进入项目、导出包或日志。
- **迁移与备份**：先研究 1.6 数据格式和旧工作台数据差异，提供只读预检、备份、可重复迁移与失败恢复；历史缺失字段标未知，不伪造来源、模型或旧配置。迁移范围、跨平台路径和回退策略需经测试后确定。
- **模型与媒体**：沿用已有模型及系统资源，先确认 Windows 二进制、模型架构、许可证和依赖版本；模型下载/更新如进入产品，须有大小、校验、来源和失败恢复，不静默下载。

## 7. 2.0 候选发布门槛

- 至少 macOS Apple Silicon 与 Windows x64 各有一个明确支持的安装包和对应平台的真实安装、出片、播放、导出证据；签名、公证及系统警告如实披露。
- 空项目到成片、退出恢复、逐镜修改再制作、失败定位、历史查找均在真实打包应用中走通；画面溢出、键盘、1024/1440 窗口及正常/空/加载/失败状态完成检查。
- 一条 AI 分镜路径使用真实外部服务验收，并保留不含凭据的模型回执；生图/视频生成只有在对应适配器完成真实验收后才宣传为可用。不要为测试反复发起付费生成。
- 自动文件检查和人工审片的结果独立可见；旧项目与已有资产不丢失。备份、迁移和异常退出恢复有可复现的测试证据。
- 发布包的 commit、tag、CI、平台、依赖清单、SHA256 和下载回验一致；发布说明不把旧包、跨平台编译或模拟服务冒充真实平台功能验收。

## 8. 需要在相关阶段确认的决策

1. **桌面产品边界**：2.0 是否将「从内容来源到发布记录/复盘」作为桌面产品闭环，同时保持独立 CLI/引擎不负责自动发布；先不改变 AGENTS.md 的既定限制。
2. **输入与编辑范围**：逐镜图片/文案/排序是否满足首版，还是需要已有视频裁切等能力；通用时间线和专业剪辑目前不纳入。
3. **Windows 验收环境与分发签名**：需要可操作的 Windows x64 环境；代码签名与 Apple 公证依赖可用的签名身份。拿不到时保留实际缺口及分发状态，不冒充已签名。
4. **付费模型首个接入对象**：先盘点已有 MuseAV 等能力与协议，再根据可用模型、成本、授权及真实回执选首条路径；本计划不假设某个模型或账号可用。
5. **数据迁移范围**：是只保证 1.6 数据安全升级，还是另提供旧 Node 工作台项目的可选导入；原文件保留、未知字段如实标记。

这些是规划中尚未确定的产品和环境问题，不影响先开展不依赖其答案的 Windows 资源盘点、数据持久化设计与现有能力审查。
