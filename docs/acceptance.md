## 未验（如实记录）

- **真实桌面窗口的视觉与交互**：屏幕锁定（`IOConsoleLocked = true`），看不到窗口画面，
  点不了原生控件（菜单栏、系统文件选择器、导出对话框）**一次都没点过**。
  上面所有界面验收都是用无界面浏览器打开**同一套前端**做的。

  但**窗口本身已验收通过** —— 锁屏时窗口照样创建，只是屏幕上看不见；
  用 Quartz 读窗口服务器能证明（不需要辅助功能权限）：

  ```
  ✓ 程序起来了（pid 87266）
    主屏 2056x1329
    muse-tv 窗口 name='muse-tv' 位置=(388,145) 尺寸=1280x868 alpha=1.00 上屏=否 完整在屏内=是
  ✓ 原生窗口已创建：尺寸合理、可见、完整落在屏幕内
  ```

  尺寸 1280×868 与 `main.go` 里配的 `Width: 1280, Height: 840`（含标题栏）一致；
  `完整在屏内=是`、`alpha=1.00`（可见）。`上屏=否` 是因为屏幕锁定 ——
  解锁后它会变「是」，脚本不拿它当失败判据。
  配套脚本，解锁后可以再确认一次：

  ```bash
  bash apps/reel-studio-wails/scripts/check-native-window.sh <muse-tv.app 路径>
  ```

  **2026-11-19 上午屏幕短暂解锁（约 10:48–10:55）期间的补充证据**：
  解锁时辅助功能 API 能读到并操作这个窗口，锁屏时读不到 —— 说明「窗口创建」
  与「屏幕是否锁定」无关，锁屏只挡住目视与截屏。

  ```
  osascript (System Events)：muse-tv 进程 windows=1
  辅助功能 API：[0] title='muse-tv' pos=(200,60) size=1600x1050
                main=true 顶层子元素 2 个
  通过 AX 移动/缩放窗口成功（设成 1600×1050 @(200,60)）
  ```

  即：窗口有标题、有 UI 子元素、能被移动和缩放、能成为主窗口。
  同一时间窗内 `screencapture -x` 成功（拿到了 4.1MB 的整屏图），
  但截到的是锁屏壁纸或别的应用 —— muse-tv 窗口在截屏前就被锁屏盖住了，
  所以**窗口内容仍未目视确认**。

  **原生控件交互已验收**（2026-11-19 上午屏幕解锁期间，用辅助功能 API 与
  CGEvent 真实鼠标事件）：

  ```
  菜单栏：4 个菜单（Apple / muse-tv / Edit / Window），各项齐全
  点「About muse-tv」→ 弹出关于对话框（窗口数 1→2）
    读到：图标 / 「muse-tv」/ 说明文字 / OK 按钮（即 main.go 配的 mac.AboutInfo）
  点「＋ 导入素材」→ 弹出 macOS 原生文件选择器（AXSheet）
    结构：AXSheet → AXSplitGroup → AXScrollArea → AXOutline
    侧边栏：Recents / Shared / Favorites / Applications / Desktop / Documents / Movies …
  两次都按 Esc 正常取消，窗口回到 1 个
  ```

  即：菜单栏可点、原生对话框可弹、系统文件选择器可弹可取消。

  **仍未验的只剩**：导出对话框（需要先有成片才能触发）、
  以及 macOS 的首次启动拦截提示（ad-hoc 签名首次打开时的 Gatekeeper 弹窗，
  只能由真人首次打开时见到）。
- **付费链路**：素材模板真生成、出镜（联网生成视频）要提交计费任务，未在验收中执行。
  两者的提示词组装、命名规则、分类落位已用单元测试覆盖。
- **Apple 公证**：只有 ad-hoc 本机签名。
- **13 集的出场角色与分镜**：YouTube 只提供标题与链接，这些信息视频里没有。
  工作台已显式标出「待分镜」，没有编造内容。
