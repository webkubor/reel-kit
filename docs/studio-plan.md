# Reel Studio 1.0 产品与实施总计划

> **文档地位**：本文件是 Reel Studio（本地视频工作台）1.0 的唯一计划真源，覆盖产品定义、质量标准、信息架构、数据模型、技术方案与分阶段实施。
> 约定：不另建平行计划文档；每完成一个里程碑，回到本文勾选任务、追加变更记录；与本文冲突的旧描述一律以本文为准并就地修订。
> 版本：v1.0（2026-11-08 初版，依据 owner 当日产品讨论定稿）

## 1. 产品定位

**面向个人创作者和小团队的本地视频工作台**：用户选择一种想做的视频，用可配置、可复盘的制作流程持续产出可直接发布的成片；发布后回填表现，据此迭代制作方法（SOP），让内容越做越好。

三条产品原则：

1. **可用 ≠ 完成**。产出必须经过质量检查和人工审片，达到「可直接发布」才算交付；生成一个 MP4 只是执行完毕。
2. **资产可积累**。声音、素材、SOP 版本都是全局资产，录一次声音、调好一套方法，之后所有视频复用。
3. **过程可追踪**。每条视频保存所用 SOP 版本、配置快照和逐步执行记录；好坏可归因，改进可验证。

成本原则：本地能稳定做的（渲染、合成、字幕、探测）走本地代码；需要创造力的（生图、配音、人物视频）才调模型，并在执行记录中明确标记来源与环节，费用发生前对用户可见。

## 2. 业务线（1.0 只做两条）

| 业务线 | key | 用户目标 | 运营价值 | 1.0 状态 |
|---|---|---|---|---|
| GitHub 项目推荐 | `github-recommend` | 输入仓库地址，产出介绍项目价值的短视频 | 技术/AI 内容账号冷启动，积累精准受众 | **首个交付，端到端可用** |
| 人物介绍商品 | `product-presenter` | 提供人物与商品素材，产出人物讲解商品的短视频 | 电商账号冷启动与内容测试 | **样片验证通过，0.2.3 起开放入口** |

- 图片、配音、BGM、字幕是**共用制作环节**，不单独成业务线（原「图片讲解视频」方向已否决）。
- 首页入口必须标明真实状态：`可用` 才给「开始制作」按钮；`建设中` 显示验证进度说明，不让用户点进去才发现缺能力。

### 2.1 GitHub 项目推荐 · 内容要求

- 输入：GitHub 仓库地址（必填）＋ 补充素材/说明（可选）。
- 输出：竖屏（视频号/小红书）或横屏成片，含旁白、字幕、项目画面。
- 内容标准：开头尽快给出看点（项目解决什么问题）；信息可追溯到仓库资料或用户补充，不把推测写成事实；技术词说清「观众为什么要关心」；讲功能时画面对应；结尾有明确动作（访问项目/收藏/关注）。
- 运营目标示例：播放、项目访问、涨粉（发布时记录，回填时核对）。

### 2.2 人物介绍商品 · 验证要求（P1，见 §10）

- 素材：**已获授权**的人物形象与商品素材，真实商品信息与卖点。
- 必须先产出可审查样片并记录效果、单条耗时、现金成本、失败点，再决定 1.0 是否开放入口；商品信息真实性、平台电商规则在开放前核实。

## 3. 核心闭环

```
选择视频类型 → 提供内容 → 确认制作方案 → 执行（可观察）
   → 检查（自动检测 + 人工审片）→ 可发布 → 导出发布
   → 记录发布 → 回填表现 → 复盘 → 保存为新版制作方法
   → 用新版本继续制作 → 比较表现 → 再迭代
```

闭环各步的证据落点：

| 步骤 | 落在哪个对象 | 关键字段 |
|---|---|---|
| 确认方案 | VideoProject.settings | 创建时冻结的 SOP 版本 + 当次配置快照 |
| 执行 | Execution + Steps[] | 每步 origin/engine/status/error/ms/asset |
| 检查 | CheckReport + ReviewChecklist | 自动检测项结果 + 人工审片逐项确认 |
| 发布 | PublishRecord | 平台/链接/日期/标签/运营目标 |
| 表现 | PerformanceRecord | 指标值/记录时间/观察窗口/来源 |
| 复盘 | ReviewRecord | 问题/假设/具体改动 → 生成的新版本号 |

**归因纪律**：单条视频好坏不能直接归因于 SOP（选题、账号基础、发布时间都影响结果）。比较只在同业务线、同平台、相近观察窗口下进行，且界面标注「小样本仅供方向参考」；数据辅助判断，不自动宣布「新版更好」。

## 4. 「可用视频」质量标准

三层验收，逐层通过才进入下一状态：

### 4.1 文件可用（自动检测，ffprobe/ffmpeg）

| 检测项 | 判据 | 方式 |
|---|---|---|
| 分辨率与画幅 | 实际输出 = 所选平台规格（竖屏 1080×1920 / 横屏 1920×1080） | 自动 |
| 时长 | > 0，且与分镜时长估算一致（容差待实测校准） | 自动 |
| 流完整 | 有视频流；预期有旁白时必有音轨；可完整解码播放 | 自动 |
| 文件大小 | 在平台当期限制内（限制值以平台规则为准，存为可配置，不写死） | 自动 |

自动检测**只报事实**（数值 + 通过/不通过），检测不到的维度明确标「待人工确认」，不显示绿色通过。

### 4.2 视听可用（人工审片清单）

字幕与语音基本同步、换行合理；平台 UI 可能覆盖的区域留安全余量；无截断/爆音/异常静音；BGM 不压人声；截图清晰不变形、不裁掉关键内容；转场不干扰理解。

### 4.3 内容可用（人工审片清单）

开头有看点；信息属实可追溯；表达像人话不像念文档；画面与解说对应；结尾有明确动作。

### 4.4 运营可用（发布前齐备）

发布平台、链接、日期、选题标签、运营目标、所用 SOP 版本全部记录在案。

**「可发布」状态的判定 = 自动检测全通过 + 人工清单逐项确认**。机器与人工的边界不混用：机器不判内容好坏，人不替机器填数值。

## 5. 信息架构与页面规格

### 5.1 导航与命名口径（用户可见词，对内概念 → 对外词）

| 内部概念 | 用户看到的词 |
|---|---|
| pipeline | 视频类型 / 制作入口 |
| SOP / SOPVersion | 制作方法（及「新版制作方法」） |
| workspace / 空间 | 我的视频 / 视频项目 |
| job / execution | 制作过程 / 一次制作 |
| origin: ai / code / import / record | AI 生成 / 本地制作 / 导入素材 / 我的录音 |

导航四入口：**开始制作 · 我的视频 · 声音与素材 · 设置**。「工作空间」一词从界面全部移除。

### 5.2 首页

| 区域 | 内容 | 行为 |
|---|---|---|
| 入口卡 ×2 | 业务线名称、一句话说明、状态（可用/建设中）、主按钮 | 可用→进入制作；建设中→显示验证说明 |
| 最近制作 | 封面、标题、状态徽章（制作中/待检查/可发布/已发布/已复盘）、更新时间 | 点击进入视频详情 |

新用户第一屏即回答「这个工作台能帮我做什么」，不出现未解释的抽象概念。

### 5.3 制作页（以 GitHub 流水线为例）

桌面双栏：左栏 = 当前阶段要编辑的内容；右栏 = 预览与试听（**始终真实画幅**，显示目标分辨率；未合成标「分镜预览」，合成后标「成片」）。顶部阶段导航：**准备内容 → 制作视频 → 检查导出**，是定位器不是强制向导，随时可回退，已填内容与已生成产物保留。

| 阶段 | 用户做的事 | 页面反馈 |
|---|---|---|
| 准备内容 | 贴仓库地址 → 读取；改标题/分镜文案；为镜头选画面 | 哪些内容来自仓库、哪些待补充 |
| 制作视频 | 确认方案（平台/声音/节奏/BGM）；点开始；看进度；修问题 | 方案摘要常显（平台·画幅·声音·节奏）；步骤时间线（见 5.4） |
| 检查导出 | 播放成片；过自动检测 + 人工清单；下载；记录发布 | 检测结果逐项；真实尺寸/时长/音轨；「记录发布」入口 |

**功能三层呈现**（不得都塞进一个「高级设置」）：

| 层级 | 内容 | 位置 |
|---|---|---|
| 默认可见 | 文案、画面、声音、发布平台、主操作 | 直接展示 |
| 就地展开 | 语速、停顿、BGM 音量、字幕样式、画面裁切 | 影响它的内容旁边（语速在声音旁，裁切在画面旁） |
| 详情面板 | 模型选择、生成参数、技术日志、执行原始数据 | 明确命名的「详情」区 |

**付费调用前置可见**：本次执行会调用哪些外部模型、依据什么计费，在「开始制作」前展示；无法估算费用时明说，不静默消耗。

**修改影响提示**：改动旁白文案时提示「将重新生成该句配音、字幕与成片；其他画面可复用」。依赖规则见 §7.3，1.0 只对已明确依赖的环节做失效复用，不承诺任意步骤重跑。

### 5.4 步骤时间线（执行可观测性的载体）

每步一行：序号 + 名称 + 来源徽章（AI 生成/本地制作/导入素材/我的录音）+ 状态（运行中/完成/失败/复用）+ 耗时 + 产物入口（试听/查看图片）。

- 失败步骤**自动展开**，显示具体错误（已脱敏）和修复入口，直达对应表单区（如「修改第 2 句旁白」），不是笼统的「任务失败」。
- 步骤数据来自后端 `report()` 上报并随 Execution 持久化，任务结束可完整回放。

### 5.5 视频详情页（制作与运营的汇合点）

| 区块 | 内容 |
|---|---|
| 成片 | 播放器、下载、尺寸/时长/音轨、当前状态徽章 |
| 制作过程 | 历次 Execution 的步骤时间线（含失败记录） |
| 制作方法 | 所用版本（v?）、当次配置快照、与上一版差异；操作：照这个方法再做一条 / 调整这条视频 / 保存为新版制作方法 |
| 发布与表现 | 平台/链接/日期/标签/目标；指标值 + 记录时间 + 观察窗口；未知留空不填 0 |
| 复盘 | 问题、假设、具体改动 → 一键生成新版本（记录 hypothesis） |

三个操作语义严格区分：**调整这条视频**只影响当前视频；**保存为新版制作方法**才生成新版本供后续视频选用；旧视频永远关联旧版本。

### 5.6 声音与素材（全局）

- 声音库：列表（名称、来源徽章、平台提示标签、试听）＋ 录制我的声音（MediaRecorder → 全局 persona）＋ 新建音色（VoxFlow 设计）＋ 从声音作品导入。页首说明「配置一次，所有项目共用」。
- 项目里只出现**选择与试听**，不出现克隆/设计/录音表单（收敛原则）。
- 素材：按项目组织；1.0 不做全局素材市场。

### 5.7 设置（低频）

连接状态（MuseAV/VoxFlow/MiniMax 及凭据注入状态）、存储目录、模型参数默认值。只在首次配置或故障时被引导进入。

### 5.8 状态机与主操作

| 状态 | 含义 | 页面上最突出的操作 |
|---|---|---|
| 草稿 | 内容/方案编辑中 | 开始制作 |
| 制作中 | 执行流水线（含排队） | 查看制作过程 |
| 制作失败 | 某步失败，输入保留 | 修复对应问题（直达入口） |
| 待检查 | 成片已生成 | 播放并检查 |
| 可发布 | 自动检测过 + 人工清单确认 | 下载发布文件 / 记录发布 |
| 已发布 | 已有发布记录 | 回填表现 |
| 已复盘 | 复盘完成（可能产生新版本） | 用新版制作方法再做一条 |

状态流转由服务端校验（如未过检查不得置「可发布」），前端只发起不裁定。

## 6. 数据模型

存储延续 `~/.reel-kit/studio/studio.json`（原子写、0600、媒体入 media/），新增对象与字段：

```
Pipeline（内置常量，不落库）
  key, name, tagline, status: 'available' | 'building', goal

SopVersion
  id, pipelineKey, version(1..n), label('v1'), name,
  config(该版本的默认配置 schema),
  parentVersionId, changeNote, hypothesis, createdAt

VideoProject（在 project 上扩展）
  id, pipelineKey, sopVersionId, title, status,
  settings(创建时冻结的运行配置快照), createdAt, updatedAt

Execution（在 job 上扩展）
  id, videoProjectId, input(快照), status,
  steps[]: { id, label, origin, engine, status, detail, error, ms, assetId, reused },
  startedAt, finishedAt, error

Asset（扩展）
  id, videoProjectId, kind(image|video|audio), origin, engine, source,
  mime, width, height, duration, hasAudio

Voice（全局，已有 voices[]）
  key(persona), name, origin('record'|'clone'|'import'), hints[], note, sampleUrl

CheckReport
  id, videoProjectId, executionId, items[]: { key, label, value, pass|null }, createdAt

ReviewChecklist
  videoProjectId, items[]: { key, label, group('content'|'av'), state('pending'|'pass'|'fail'), note }

PublishRecord
  id, videoProjectId, platform, url, publishedAt, tags[], goal

PerformanceRecord
  id, publishRecordId, metrics{plays?,likes?,…}, recordedAt,
  observationWindow, source('manual'), note

ReviewRecord
  id, videoProjectId, findings, hypothesis, changes, createsVersionId
```

约束：SopVersion 一经引用不可变（改配置 = 新版本）；settings 快照随视频保存，SOP 后续演进不回写旧视频；迁移时旧 project/job 数据保留并补默认字段。

## 7. 技术方案

### 7.1 现有基础（已提交 c31e552 + 在途改造）

- `src/studio/server.mjs`：本地 HTTP（127.0.0.1:4390）、任务队列、CSP/Origin 防护、`X-Reel-Action` 头校验。
- `src/studio/recommendation.mjs`：GitHub 抓取 → 逐句配音（VoxFlow）→ playwright 渲染帧 → ffmpeg 合成，已带 `report()` 步骤上报与 origin 标记（在途）。
- `src/studio/providers.mjs`：H3 视频 / MuseAV 图片 / VoxFlow 语音适配，产物带 origin/engine 与尺寸探测（在途）。
- `src/studio/process.mjs`：`probeBytes`（ffprobe 尺寸/时长/音轨）。
- `studio/` 前端：app.js + recommendation-controls.js（平台/声音/节奏/BGM 已可选、竖屏预览已生效）。
- 已验证：端到端生成 1080×1920、16.13s、含音轨的成片；换音色只重生成配音、帧复用。

### 7.2 新增/改造模块（按 2026-11-08 实际实现修正）

| 模块 | 实际文件 | 职责 |
|---|---|---|
| SOP/复盘/发布/表现 | `src/studio/workflow.mjs`（新） | sopVersions/publishes/performance/reviews 存储、快照冻结、动作门禁校验（原计划的 pipelines/status 合并于此） |
| 质量检测 | `src/studio/server.mjs` `/api/workflow/quality` | ffprobe/ffmpeg 自动检测（原计划独立 quality.mjs，实现为端点） |
| 发布/表现/复盘端点 | `src/studio/server.mjs` `/api/workflow/*` | select-sop / quality / review-check / publish / performance / review |
| 首页/制作页前端 | `studio/app.js`、`studio/index.html` | 业务入口卡、阶段导航、真实画幅预览 |
| 复盘闭环前端 | `studio/workflow-panel.js`（新） | 检查→确认→发布→表现→复盘→版本选择 全链 UI |
| 声音库前端 | `studio/voice-library.js` | 全局声音管理（录音/导入 + 原文 + 试听确认，需 VoxFlow 0.10.1+） |

### 7.3 依赖与复用规则（1.0 明确支持的失效面）

| 改动 | 失效并重生成 | 可复用 |
|---|---|---|
| 旁白文案（某句） | 该句配音、字幕时间、成片 | 其他句配音、全部画面帧 |
| 音色/表达方式 | 全部配音、成片 | 画面帧 |
| 语速/停顿 | 成片（配音按策略复用或重生成） | 画面帧 |
| 发布平台（画幅） | 画面帧、成片 | 配音 |
| 画面素材/裁切 | 对应镜头帧、成片 | 配音 |
| BGM/音量 | 成片 | 配音、帧 |

复用判定依据已生成的 Asset 与 settings 差异，命中即标 `reused`，时间线显示「复用已生成」。

### 7.4 端点清单（新增）

```
GET  /api/home                          入口卡 + 最近制作
GET  /api/pipelines                     业务线列表（含状态）
GET  /api/pipelines/:key/versions       SOP 版本列表
POST /api/videos                        从入口创建视频项目（冻结版本+快照）
GET  /api/videos/:id                    详情（成片/过程/方法/发布/表现/复盘）
POST /api/videos/:id/check              运行自动质量检测
POST /api/videos/:id/transition         状态流转（服务端校验证据）
POST /api/videos/:id/publish            记录发布
POST /api/videos/:id/performance        回填表现
POST /api/videos/:id/review             保存复盘（可同时创建新 SOP 版本）
```

既有 `/api/jobs`、`/api/assets`、`/api/voice/*`、`/api/voices` 保留并按新模型对齐字段。

## 8. 1.0 成功标准与观察指标

**定性标准**：新用户选定一个仓库后，不经开发者协助完成配置 → 制作 → 检查 → 导出 → 记录发布；失败能定位步骤；愿意做第二条并回填表现调整 SOP。

| 问题 | 观察方式 | 备注 |
|---|---|---|
| 能否独立完成 | 首次进入到导出成功的比例、耗时、求助点 | 首轮可用性测试：5 名目标用户，不打预讲，任务=找入口/做第一条/换声音/改一段内容/找回历史/找到制作方法；设计目标 ≥4 人无口头指导完成 |
| 是否持续使用 | 第二条视频制作率、声音/SOP 复用率 | 重复使用比单次生成更能验证价值 |
| 复盘是否被用 | 回填→复盘→新版→再制作的漏斗 | 每步计数，不只数生成量 |
| 单条成本 | 本地耗时 + 外部模型调用次数与费用 | 按真实模型与账号实测，不预设 |
| 内容是否变好 | 同平台相近窗口的版本表现对比 | 小样本仅方向参考 |

指标目标值在收集首轮数据后制定，不提前拍数字。
