# 沸腾之雪 · 资料入库技能

> 适用场景：
> - 用户直接在聊天里发长段人物小传
> - 用户补充某角色的正序/倒序人物传
> - 用户补充第一部时间线、势力设定、地图节点、关系线
> - 当前目标不是写正文，而是建设小说资料库

## 核心原则

1. 先收素材，再改写
2. 用户原话是第一手资料，必须先完整落盘，不能只总结不存档
3. 结果必须在对话窗口直接告诉用户“已保存到哪里”
4. 微短剧素材是参考，用户口述的新设定优先级更高
5. 原始口述与结构化文档分层存放，避免互相污染

## 标准流程

### 第一步：判断资料类型
收到用户长文本后，先判断属于哪类：
- 人物
- 时间线
- 地图/地理
- 势力/世界观
- 关系线
- 悬念/真相

### 第二步：先原样存档
不要急着改写。
优先把用户原文完整写入“原始口述”目录。

文件名规则：
- 人物：`人物/原始口述/角色名·正序人物传.md`
- 时间线：`时间线/原始口述/主题名.md`
- 关系：`关系/原始口述/主题名.md`
- 地图：`地图/原始口述/主题名.md`

文件头统一写：
- 来源：用户直接提供
- 状态：一手原始设定 / 初始版本 / 待抽离
- 用途：后续用于结构化拆分

### 第三步：回执用户
保存后立即明确回复：
- 看到了
- 已保存
- 具体路径
- 后续会用于什么抽离工作

不能只说“收到”或“我记住了”。

### 第四步：再做结构化抽离
当原始素材达到一定数量后，再抽离为：
- 人物档案
- 时间线节点
- 关系网
- 设定冲突清单
- 待补空缺清单

## 抽离建议

### 人物类至少抽这些字段
- 姓名
- 身份/阵营
- 年龄阶段
- 核心经历
- 性格底色
- 关键关系
- 已知秘密
- 不知道的信息
- 第一部当前状态
- 待确认点

### 时间线类至少抽这些字段
- 相对时间
- 事件名称
- 涉及角色
- 事件结果
- 影响范围
- 信息掌握者
- 是否公开
- 待确认点

## 特别提醒

1. 资料建设期 ≠ 写正文期
当前阶段先建资料库，不默认进入章节创作。

2. 不要把用户原始口述直接覆盖到已有人物小传
原始资料先独立保存，之后再人工/半自动抽离。

3. 如果用户连续发送多名关键人物
优先持续入库，不要打断用户节奏问一堆问题。

4. 如果已有旧设定与用户新口述冲突
不要擅自裁决，先进入“待补设定/待确认清单.md”。

## 本次会话验证过的有效做法

- 用户发送《苏梦城·正序人物传》时，先完整落到：
  `人物/原始口述/苏梦城·正序人物传.md`
- 用户发送《慕夕歌·正序人物传》时，先完整落到：
  `人物/原始口述/慕夕歌·正序人物传.md`
- 落盘后立即把保存路径回报给用户，用户确认这种方法可行
